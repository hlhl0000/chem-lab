# 화학 탐구실 — 사이트 구조 안내

자바실험실처럼 **대문 페이지에서 여러 시뮬레이션으로 이동하는 사이트**의 최소 골격입니다.
프레임워크·빌드 도구 없이 순수 HTML/CSS/JS만 씁니다.

## 폴더 구조

```
화학탐구실/
├── index.html          ← 대문. 카드 목록·검색·분류 필터
├── sims.js             ← ★ 시뮬레이션 카탈로그 (여기만 고치면 목록이 바뀜)
├── shared/
│   ├── style.css       ← 사이트 공통 디자인 (색·버튼·카드·표)
│   └── nav.js          ← 모든 페이지 위쪽 이동 메뉴를 자동 삽입
├── gas/
│   ├── index.html      ← 시뮬레이션 화면 (HTML)
│   └── sim.js          ← 시뮬레이션 물리·그리기 (JS)
└── README.md
```

핵심은 **`sims.js` 한 곳이 사이트 전체의 목차 역할**을 한다는 점입니다.
대문의 카드도, 각 시뮬레이션 페이지 상단의 "다른 시뮬레이션으로 이동" 메뉴도
모두 이 배열을 읽어서 자동으로 만들어집니다.

## 새 시뮬레이션 추가하는 법 (3단계)

1. 폴더를 만든다 — 예: `titration/`
2. 그 안에 `index.html`을 만든다. `gas/index.html`을 복사해서 고치는 게 가장 빠릅니다.
   페이지 맨 아래 세 줄은 그대로 두고 `data-current`만 새 id로 바꾸세요.

   ```html
   <script src="../sims.js"></script>
   <script src="../shared/nav.js" data-base=".." data-current="titration"></script>
   <script src="sim.js"></script>
   ```

3. `sims.js`의 해당 항목에서 `ready: false`를 `true`로 바꾼다.

끝입니다. 대문 카드와 이동 메뉴에 자동으로 나타납니다.
`sims.js`에는 이미 7개 시뮬레이션이 `ready: false`(준비 중)로 등록돼 있으니,
만들고 싶은 것부터 골라 만들면 됩니다.

## 디자인을 한 번에 바꾸려면

`shared/style.css` 맨 위 `:root` 안의 색깔 값만 고치면 사이트 전체에 반영됩니다.

```css
--accent:#2563eb;   /* 이 한 줄로 버튼·링크·강조색이 전부 바뀝니다 */
```

## 로컬에서 보기

`index.html`을 더블클릭하면 대부분의 환경에서 그대로 열립니다.
(`fetch`나 ES 모듈을 쓰지 않고 일반 `<script src>`만 쓴 이유입니다.)

브라우저 보안 설정 때문에 안 열린다면 VS Code의 **Live Server** 확장을 설치하고
`index.html` 우클릭 → *Open with Live Server* 를 쓰세요.

## 인터넷에 올리기 (GitHub Pages)

1. GitHub에서 **Public** 저장소를 만든다 — 예: `chem-lab`
2. 이 `화학탐구실` 폴더 **안의 내용물**을 저장소 최상단에 올린다
   (폴더째 올리면 주소에 `/화학탐구실/`이 한 겹 더 붙습니다)
3. Settings → Pages → Source: *Deploy from a branch* → `main` / `(root)` → Save
4. 1~2분 뒤 `https://<아이디>.github.io/chem-lab/` 에서 열립니다

학생에게는 이 주소를 QR코드로 배포하면 편합니다.
개별 시뮬레이션 주소는 `https://<아이디>.github.io/chem-lab/gas/` 형태입니다.

> 폴더 이름을 한글(`화학탐구실`)로 두면 주소에 한글이 들어가 링크 공유 시 깨져 보일 수 있습니다.
> GitHub에 올릴 때는 영문 폴더명(`gas`, `titration` 등)을 쓰는 지금 구조를 권합니다.

## 태블릿·모바일 검증 결과 (Chromium 엔진 실측)

각 해상도의 iframe에 실제로 렌더링해 측정했습니다.

| 기기 | 가로 스크롤 | 레이아웃 | 터치 타깃 |
|---|---|---|---|
| iPad mini 세로 (744) | 없음 | 1단, 캔버스 699px | 버튼 44px, 슬라이더 38px |
| iPad 10.9 세로 (820) | 없음 | 1단, 캔버스 775px | 버튼 44px, 슬라이더 38px |
| 갤럭시탭 세로 (800) | 없음 | 1단, 캔버스 755px | 버튼 44px, 슬라이더 38px |
| iPad Pro 11 가로 (1194) | 없음 | 2단 (668+495), 카드 4열 | 버튼 44px, 슬라이더 38px |
| 휴대폰 (320~430) | 없음 | 1단 | 버튼 44px |

- 모든 터치 타깃이 애플·구글 권장치 44×44 px 이상
- 입력창 글자 16px → **iOS Safari 탭 시 자동 확대 없음**
- 확대/축소 차단(`user-scalable=no`) 안 함 → 접근성 유지
- hover 효과는 `@media (hover:hover)`로 감싸 터치에서 들러붙지 않음

### 검증 중 발견해 고친 것

1. **입력창 글자가 14px로 남아 iOS에서 자동 확대되던 문제** —
   각 페이지의 `<style>`이 공통 CSS보다 뒤에 오기 때문에 같은 우선순위에서는 페이지 쪽이 이깁니다.
   공통 CSS의 터치 규칙에 `html`을 붙여 우선순위를 높여 해결했습니다.
2. **휴대폰 360px에서 상단 네비게이션이 가로로 넘치던 문제** —
   480px 이하에서 '전체 목록' 링크를 숨기고 선택 상자를 줄였습니다.

> 실측하지 못한 항목: 실제 기기의 터치 제스처 반응과 애니메이션 프레임률.
> 입자 수를 최대(300개)로 올리면 구형 태블릿에서는 느려질 수 있으니,
> 배포 후 실제 학생 기기에서 한 번 확인해 보세요.
